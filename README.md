# AI Product Card Generator

Прототип сервиса для генерации товарных карточек
контрольно-измерительных приборов с использованием
OpenAI API.

Разработан в рамках тестового задания на позицию
AI-разработчика.

## Возможности

- Приём информации о товаре из JSON.
- Валидация входных данных через Pydantic.
- Генерация SEO-контента с помощью OpenAI GPT.
- Структурированный ответ LLM.
- Формирование списка технических характеристик.
- Выявление отсутствующих данных.
- Проверка качества сгенерированного контента.
- Экспорт результатов в JSON и Markdown.
- Демонстрационный режим без обращения к API.
- Автоматические тесты с pytest.

## Технологии

- Python 3.13
- OpenAI Python SDK
- Pydantic 2
- python-dotenv
- pytest

## Архитектура

Обработка товара состоит из нескольких этапов:

1. Чтение входного JSON.
2. Валидация и нормализация данных.
3. Формирование запроса для LLM.
4. Получение структурированного ответа.
5. Проверка качества сгенерированного текста.
6. Объединение текста и исходных характеристик.
7. Экспорт карточки в выбранном формате.

Основные компоненты:

- `models.py` — модели входных и выходных данных.
- `prompts.py` — системный промпт.
- `generator.py` — генерация и сборка карточки.
- `quality.py` — проверка качества результата.
- `export.py` — экспорт JSON и Markdown.
- `main.py` — CLI-интерфейс.
- `generate_demo_examples.py` — автономная демонстрация.
- `tests/` — автоматические тесты.

## Установка

Требуется Python 3.13.

Клонировать репозиторий:

```bash
git clone https://github.com/dedepy/ai-product-cards-tt.git
cd ai-product-cards-tt
```

Создать виртуальное окружение:

```bash
python -m venv .venv
```

Активировать на Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Установить зависимости:

```bash
python -m pip install -r requirements.txt
```

## Настройка OpenAI API

Создать файл `.env` на основе `.env.example`.

Указать параметры:

```dotenv
OPENAI_API_KEY=your_api_key_here
OPENAI_MODEL=gpt-5-mini
```

Настоящий API-ключ хранится только локально
и исключён из Git через `.gitignore`.

Для реальной генерации необходим действующий
API-ключ с доступной квотой.

## Использование

Проверить входной JSON без обращения к API:

```bash
python main.py examples/dm02.json --validate-only
```

Сгенерировать карточку через OpenAI:

```bash
python main.py examples/dm02.json
```

Сохранить результат в JSON:

```bash
python main.py examples/dm02.json --output results/dm02.json
```

Сохранить результат в Markdown:

```bash
python main.py examples/dm02.json --output results/dm02.md
```

## Демонстрация без API

Для проверки основных компонентов без OpenAI API
предусмотрен отдельный сценарий:

```bash
python generate_demo_examples.py
```

Он использует заранее подготовленные тестовые ответы
в `examples/mock_responses/`.

Результаты сохраняются в `examples/results/`
в форматах JSON и Markdown.

Демонстрационные ответы не являются результатами
реального вызова GPT.

Второй товар является синтетическим учебным примером
для проверки работы с неполными данными.

## Формат результата

Карточка включает следующие поля:

- `seo_title` — SEO-заголовок.
- `seo_description` — SEO-описание.
- `search_queries` — поисковые запросы.
- `commercial_text` — коммерческое описание.
- `characteristics` — технические характеристики.
- `missing_fields` — отсутствующие данные.
- `validation_warnings` — предупреждения качества.

## Валидация результата

Проверяются:

- Наличие непустого SEO-заголовка.
- Максимальная длина заголовка — 70 символов.
- Максимальная длина описания — 1200 символов.
- Предупреждение при длине описания менее 800 символов.
- Количество поисковых запросов — от 3 до 5.
- Отсутствие пустых и повторяющихся запросов.
- Наличие коммерческого блока.

Если входной информации недостаточно, допускается
описание короче 800 символов с соответствующим
предупреждением.

Такой результат считается черновиком, требующим
доработки, а не полностью соответствующим SEO-требованиям.

## Защита от выдуманных характеристик

Технические характеристики итоговой карточки
формируются непосредственно из входного JSON.

LLM генерирует только текстовые поля.

Если значение характеристики отсутствует,
оно отображается как `данных нет`.

Промпт дополнительно запрещает придумывать
технические параметры, сертификаты, материалы
и неподтверждённые области применения.

При этом промпт и структурированный вывод
не обеспечивают абсолютной защиты от галлюцинаций
в текстовых блоках.

## Промпты

Используется системный промпт, задающий:

- Роль технического B2B-копирайтера.
- Требования к SEO-контенту.
- Запрет на выдумывание характеристик.
- Правила обработки неполных данных.
- Требования к поисковым запросам.
- Игнорирование инструкций внутри товарных данных.

Входной JSON передаётся отдельно как данные товара.

Для получения структурированного ответа
используется Pydantic-модель `GeneratedText`
и OpenAI Responses API.

## Тестирование

Запуск всех тестов:

```bash
python -m pytest -v
```

Тестами покрываются:

- Валидация входных данных.
- Нормализация характеристик.
- Обработка некорректного JSON.
- Проверка качества результата.
- Генератор с подменённым LLM-клиентом.
- Экспорт в JSON и Markdown.
- Ошибки CLI и отсутствие API-ключа.
- Обработка HTTP 429.
- Демонстрационные сценарии.

Для тестирования внешней интеграции используются
поддельные ответы API без сетевых запросов.

## Принятые технические решения

### Pydantic

Используется для проверки входного JSON,
типизации данных и получения структурированного
результата LLM.

### Разделение ответственности

Работа с API, бизнес-валидация, формирование
карточки и экспорт разделены по модулям.

### Работа с неполными данными

Отсутствующие значения явно отмечаются.
Программа не дополняет технические параметры
предположениями.

### Тестируемость

Логика сборки карточки отделена от вызова API.
Это позволяет тестировать бизнес-логику
без доступа к GPT.

## Ограничения

1. Прототип не включает веб-интерфейс, БД и CMS.
2. Входные данные загружаются из локального JSON.
3. Семантическая достоверность AI-текстов
   не гарантируется автоматическими проверками.
4. Автоматическая повторная генерация при нарушении
   SEO-ограничений не реализована.
5. Результат желательно проверять контент-менеджеру.
6. Реальная генерация GPT требует доступной API-квоты.
7. Интеграция с реальной GPT пока не подтверждена
   успешным API-запросом из-за отсутствия кредитов.
